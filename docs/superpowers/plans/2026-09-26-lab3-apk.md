## Global Constraints

- Application ID `ua.meti.tuman.lab3`, title `Меті Туман LAB 3`, minimum API 26.
- No INTERNET permission; include the model in APK assets.
- Source branch is isolated from main; no edits in android-lab2 or existing web folders.
- BC/CR uses its own airlight and weighted contextual regularization; AI uses verified trained weights.
- Snapshot comparisons always use the exact same source pixels for original and processed views.
- Switching source/algorithm or disabling processing invalidates outstanding work; no queued processing backlog.
- Logs distinguish processed FPS, source samples, processing time and result age. No claim of full camera-to-screen latency.

## Review Focus

1. Image rotation and unusual aspect ratios must preserve geometry and match both views.
2. Media permission denial, activity pause and closing while inference runs must release camera/player and ignore results.
3. Black/white/small images and airlight near a boundary must produce finite bounded pixels.
4. Missing/corrupt models must report an explicit failure, leave original visible and never masquerade as AI.
5. Repeated mode switches must keep at most one heavy computation and not revive old results.

### Task 1: Independent package and deterministic processing primitives

**Files:** `android-lab3/`, new `.../live/BcDehaze.java`, `FrameGate.java`, corresponding unit tests.

**Interfaces:** `BcDehaze.process(int[] argb,int width,int height,int mapLimit)` returns `Result` with same-sized `argb`, stage timing and airlight. `FrameGate` issues a generation token with `begin()`, invalidates through `reset()`, and `finish(token)` reports whether a result remains current while releasing busy state.

- [ ] Write failing tests for numeric primitives, bounded output and stale-result rejection; run and inspect failure.
