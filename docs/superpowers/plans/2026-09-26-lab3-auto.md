# LAB 3 automatic selection

User asks to make the app switch algorithms itself. Continue the authorized APK workflow inline. Base is the actually delivered, CI-verified f53a6f7, not the alternative local compact-layout commit. This is an addition to the existing snapshot dispatch flow.

Goal: AUTO selected by default; photo processes after load; camera/video re-evaluate candidates periodically. The user can still choose any manual mode. Separate application ID ua.meti.tuman.lab3.auto and title Меті Туман LAB 3 AUTO preserve the comparison APK.

Design: deterministic no-reference quality heuristic compares every result with the same source at <=256px. Reward moderate contrast/detail gains; penalize new clipping, large luminance/color shifts and extra detail in flat input regions. Include original as a candidate. This is a heuristic, not a guarantee of perceptual quality. For video, penalize processing time and exclude a candidate for 30 seconds after an error or >2000ms processing. Probe every 6 seconds, otherwise run only the selected algorithm. Switching needs two consecutive probe wins, >=3 score improvement and >=8 seconds dwell. Failure or strong image damage falls back to original immediately. Photo uses immediate selection and full native output dimensions (AI remains <=256px).

Implementation and tests:
1. AutoQuality.java and AutoPolicy.java: hand-built pixel tests (identity, clipped/black outputs, noise, useful contrast), policy sequences for initial selection, ties, hysteresis, cooldown, failure, and reset. Compile and run via local ECJ/JUnit; then full Android unit suite in CI.
2. AutoProcessing.java: run candidates independently with per-candidate exceptions; score matched resized pixels. Add AUTO integration in Lab3Activity using existing one-worker/generation gate; commit selection only after a valid result. Retain manual comparison/export and labels identifying snapshots. Add emulator tests for automatic photo processing, switching to manual during queued inference, off during inference, source change, and per-algorithm failure fallback.
3. Build separate APK with existing pinned model/parity pipeline and arm64 runtime. One independent final code review, fix material findings with reproducing tests, full CI, artifact checksum verification, delivery and short Ukrainian guide.

Review focus: stale AUTO decisions after source/strength/mode/pause changes; photo auto retry after resume; no auto backlog; manual exports match shown result; partial algorithm failure keeps usable results; failed/slow algorithms do not get retried every frame.

Ruling: latest request concerns automatic selection in the delivered APK. Existing web remains the prior LAB; this change does not add web BC/AI. Heavy AUTO modes remain matched snapshots, not full-rate video replacement.
